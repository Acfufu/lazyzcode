# ADR-0002 · init-deep 的角色分配：模型提案 / 人批准 / 代码执法 / doctor 巡逻

日期：2026-09-08 · 状态：已拍板 · 关联：AGENTS.md §5 表达层级、决策 #8/#16、`docs/research-lazycodex-to-zcode.md` §四（init-deep-z 原计划）

## 决策

init-deep（分层 AGENTS.md 项目记忆）按四层角色落地，**确定性骨架进产品**：

1. **模型 = 提案者**：独立技能 `lazyzcode:init-deep` 做语义工作（读目录、写草稿），任何写入先出草稿，人点头才落盘；已有文件只出建议补丁，绝不静默改——手工 AGENTS.md 是维护者的宪法。
2. **人 = 批准者**：所有草稿人工把关。
3. **代码 = 执法者**：`core/agentsmd.js` 实现资格谓词（构建入口文件存在 / 直接文件数 >40 / 根文件提及 `<dir>/`，任一即够格）与覆盖审计（够格而无子文件且未被根提及=缺口；行数软上限根 150 / 子 40），纯代码、零依赖、两次跑结果一致。模型不产出「资格」这个事实，只消费它。
4. **doctor/CI = 巡逻队**：doctor 新增 `agents-md` 检查（warn-only，根文件缺失=skip 不催 adoption）；`lzy agents-md` 出详单（退出码 0/1）；CI 可选片段跑同一条命令。

默认深度 3 层、零旗标（决策 #16 零配置面精神）；用户在对话中可临时覆盖。产出只写 AGENTS.md 层（仓库/团队面，随 git 入库）；本机个人面归内置 memory（zw finish 收尾仪式），两面互补不重叠。

## 依据

- 「哪些子目录值得建」若纯靠模型心证，两次跑结果漂移、不可审计——与纪律层产品气质相悖；若纯用计数公式，docs/（19 个同质文件不该建）与 cli/（3 个文件但是独立执行边界、该建）这类语义场景必错。
- 混合方案：判据写成代码（可复现），语义留给草稿（准确性），人守住写入（安全）。这与计划门、证据门同构——模型主张，机器执行。
- ZCode 引擎原生逐级读 AGENTS.md（多源合并 + 100KB 截断）：分层 + 行数上限是防截断的结构手段；子目录文件自动合并，零配置。
- 「根提及 = 根声明覆盖」让豁免不需要新状态文件：刻意不建子文件的目录在根文件仓库地图里写一行 `<dir>/` 即显式登记。

## 备选与否决

- **纯技能文本（判据清单写进 SKILL.md，无代码）**：零代码成本，但同一仓两次跑结果漂移、doctor 无法巡逻，被否。
- **打分公式 + --depth 旗标**：可量化但语义误判（上述 docs/ vs cli/ 反例），且引入配置面，被否。
- **只做根文件不分层**：丢掉 monorepo 最大受益点，与上游 lazycodex `$init-deep` 同构性弱，被否。
- **init-deep 顺带写内置 memory**：与 zw finish 收尾仪式职责重叠，两面边界模糊，被否。
