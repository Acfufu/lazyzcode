# ADR-0004 · Stop 拉回走认领制：goal 目录级共享 + 会话认领集

日期：2026-09-08 · 状态：已拍板 · 关联：决策 #13（Stop 预算细分）、#17（本决策）、
ADR-0003（无人值守唤起协议）、红线 #2（共享池预留）、上游颗粒度核查（2026-09-08，
lazycodex@10f9558 / OmO@a470d3d 源码实测）

## 决策

Stop 钩子的拉回资格从「目录级」（cwd 有 goal.json 即拉）细化为**认领制**：goal.json
保持目录级共享（跨会话续接、无人值守接管、`loop status` 全局视图全保留），新增会话
**认领集**——认领记录写现有 `sessions/<sessionId>.json`（UPS 触发词命中时 +`claimedAt`，
零新命令）；Stop 拉回只作用于认领会话。配套四条：

- **多认领集合语义**：多会话可同时认领。引擎无 SessionEnd（§3.1）→ 无可靠释放信号 →
  独占认领的残留会永久挡住新会话、循环饿死；重复劳动靠纪律文本与 status 可见性缓解，
  不做互斥（活性不可探测，互斥是假安全）。
- **单调收紧兼容**：goal 从未被任何会话认领 = 维持现状目录级行为；首个认领发生即转为
  仅认领会话可被拉。老用户零迁移。
- **进度感知振数**（同批）：拉回后 goal 步骤零推进才累计振数，两振写 stuck 标记提前
  弃拉（省引擎共享池）+ stuck 进 status/doctor 可观测；**拉回上限仍 2**，红线 #2 不破
  （引擎 3 次共享池下「有进展归零」会超发，被引擎拒）。
- **读面**：`loop status` 显示认领集/待认领（孤儿）+ doctor 孤儿循环检查行；
  SessionStart 广播保留（新会话知情通道，无人值守依赖），文案加「发 zw 继续以接管」CTA。

## 依据

- 竞品实锤：lazycodex 状态键 = cwd+sessionId（`.omo/ulw-loop/<sessionId>/goals.json`，
  旁路会话天然无状态不拉）；OmO boulder 用复数 `session_ids` + 用户中断检测。我方目录级
  闸门是三家里最粗——旁路会话（纯问答）被捎进循环靠 2 次预算封顶止损（2026-09-08 活体
  撞到三次，同一会话）。
- 认领动作选触发词而非新命令：接手循环的真实习惯就是句首「zw 继续」（ADR-0003 无人值守
  唤起 prompt 同一条路），认领是触发词语义（进入 zw 纪律语境）的自然推论，零新命令面、
  零文档膨胀。
- 集合语义是约束推导而非偏好：§3.1 无 SessionEnd 事件，独占方案在「前会话判死/关窗」
  场景下必然死锁。

## 备选与否决

- **会话私有制**（lazycodex 式 `<sessionId>/goals.json`）：模型更纯，但无人值守唤起的
  新会话需要新接管协议（扫目录找孤儿目标）、doctor 状态卫生/证据归档路径全改、现存循环
  要迁移，生态兼容成本高于收益，否。
- **SessionStart 问询式认领**：问询打在旁路会话头上 = 骚扰换形式转移；无人值守无人应答
  还得开豁免；引擎 7 事件无交互往返原语（注入文本+解析回复=钩子里造对话），否。
- **`lzy loop claim` 显式命令**：认领写面的唯一消费者是会话内 Stop 钩子，裸 shell 认领
  是空操作（没有 Stop 事件会 fire，CLI 只记账不干活）；`loop status` 认领显示属读面随批
  做，无需 claim 命令。出现程序化认领真实需求再补，记备选。
- **进度感知「计数归零」**（lazycodex 原形态）：其语义建立在引擎允许更多续跑上；本引擎
  3 次共享池硬顶（§3.2/3.3）下归零即超发，降级为「早停 + stuck 可观测」，部分吸收。
- **跨项目全局清单**（一屏看所有仓库的循环）：各项目 `.lazyzcode/` 互不联通是无中央
  账本的隐私/零遥测设计；跨项目需目录发现/登记机制，独立增量待真实需求，记备选。

## 修正案（2026-09-09，ADR-0006 同批）

- **认领写面收窄至唤起级**：原案「UPS 触发词命中即写 claimedAt」（全谱：句首 zw /
  显式名 / 任意位置 ulw·ultrawork）过宽——活体 specimen：会话正文「对比 /ulw 的写法」
  被句中别名匹配误认领，该旁路会话遭 Stop 拉回、致盲真主会话。修正：认领写面收窄为
  **唤起级触发**（句首 zw / 显式 `lazyzcode:zw` / 句首 ulw·ultrawork）；通知注入维持
  全谱不变。executing 闸门、集合语义、拉回上限 2 均不动。
- 实现在 `plugin/hooks/trigger.js`（`ALIAS_INITIAL_RE`），矩阵测试见
  `test/claim.contract.test.js`。

## 修正案二（2026-09-10，goal comparator-salvage）：依赖图并行认领记债

**记债不实现**：计划项声明依赖边、`step` 派发从「取下一步」变「取任一无阻塞步」、多会话
可并行认领独立步骤（FLT 形式化工程的 DAG 模式）。同目标多工人是 worktree 隔离覆盖不了的
形态（worktree=跨目标并行），但当下受限流纪律约束——GLM 账号级限流实测无固定并发阈值、
zw 默认串行，图的重心收益只在并行存在时成立，硬上=没人需要的地图+结构性改动（语法/派发/
证据门/账本全适配）。**升格触发器（任一）**：①doctor 实测带内允许 ≥2 并行会话；
②同目标撞槽再发；③多模型分发现实化（并行会话分属不同 provider 账户）。**前置件**：
角色指模型走宿主 10-provider 目录（宪法 §3.5 不自研模型路由不推翻）；doctor 经验并发带
按 provider 分桶各测。
