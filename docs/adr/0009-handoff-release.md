# ADR-0009: 交接放行（Stop 钩子尊重交接快照）

日期：2026-09-10 ｜ 状态：已拍板 ｜ 关联：ADR-0004（认领制）、决策 #22、事故 sess_95421d3d

## 背景

真实事故（bili-manager 仓，2026-09-09）：模型陷入同工具空转吸引子 47 分钟（79 连调）后正确做出收尾——写交接快照、明确请求用户开新上下文——但 Stop 钩子（旧目录闸门版）把它拉回，又空转 15 分钟，最终用户手动杀会话。振数机制能止损但不能给「正确收尾」以体面出口：模型主动交还执行权与「做不完被拉回」在钩子眼里不可区分。

## 决策

`lzy loop handoff --snapshot <file>` 落目录级匿名标记 `loop/handoff.json`（快照必填、存在、mtime≤24h）；Stop 钩子在认领闸门后、stuck/预算闸门前一次性原子消费（unlink 恰一赢家），放行输出显式 `continue:false`（不入引擎 3 池，不耗 continues 预算），消费同时清本会话 stall/stuck/lastDoneCount；reset/abandon 清理收编该标记。

## 依据

- **与「不做完不停」的边界**：交接不是半途而废——循环状态全在盘上（goal.json/计划文件），交接是把执行权交还用户并约定新上下文续跑；拉回一个已正确收尾的会话只会烧预算产出垃圾。
- **匿名目录级标记而非会话精确归属**：模型在 Bash 环境拿不到自己的 sessionId（引擎只注入 hook env），一切要求模型转抄会话身份的设计都在最需要逃逸的时刻制造新失败面（双审 P1）。unlink 原子性保证并发同停时恰一赢家。
- **消费制一次性**：放行后同会话继续干活，下次 Stop 正常拉回——交接出口不构成永久免检。
- **不耗预算**：continue:false 不满足引擎续跑判据（Z:460139-460157），与 stuck 弃拉同形态；预算仍整段留给「未收尾却被打断」的拉回。

## 已知边界

多认领集合下 A 会话登记交接、B 会话恰在其 Stop 窗口内先停：B 消费标记被放行（带说明上下文），A 照常按剩余预算被拉。发生条件苛刻（双活跃会话秒级同停），后果轻微且无状态损坏；A 可再登记。若多认领撞窗成为现实（决策 #21 升格触发器 territory），可在匿名标记上加可选 `--session` 精确归属，现设计是其真子集。

## 备选与否决

- SessionStart 注入 sessionId + `--session` 精确指向：归属严格但多一个注入面、模型转抄长 UUID 脆弱、锁移植破层——否决（可后加）。
- 计划文件标记/钩子扫描 transcript：会话级语义写进 slug 级载体/格式耦合误报面大——否决。
- 放行消耗预算：把正确收尾当拉回扣账，惩罚最优行为——否决。
