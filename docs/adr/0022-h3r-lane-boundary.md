# ADR-0022 · H3R 高危步门的车道边界与休眠语义

日期：2026-09-21 · 状态：已接受 · 拍板：roadmap §⑰ Q4（用户 grilling 逐问锁定）· 实现 goal `v022-bat2-h3r`

## 决定

H3R（高危步骤执行前的人权门，SOTA V3 门族）的**机器形态原型**落主线，但只在一个地方执法：

**车道边界口径**——门**只在无人值守的 `lzy loop drive` 段循环里生效**。交互会话天然免门，并且**就是**恢复路径：停摆发生后，人在交互会话里读快照、确认、按计划推进。这与 ADR-0020 的 `assertDriveEligible`（drive 入口拒 HIGH+）是**同一语义**的细粒度版本——都是把「无人可批的风险」转成人类任务。

停摆形态（Q4）：**段内拒执行 + 干净收束 + handoff 快照**，收束因是 `#28` 收束因族的新因 `h3r`，`ok:true`（与 `stuck`/预算尽同走退出码 0 的干净通道），不新开鉴权面、不新立批准记录族。

## 实现坐标与判定面

- **代码**：`core/h3r.js`（判定面与词表）+ `core/drive.js` 段循环里的检查块。
- **位置**：紧跟段首三门（`readGoal` → `assertDriveEligible` → `heartbeatLease`）之后、墙钟判之前。理由：此处「下一步是谁」已可判，而段**尚未 spawn**——命中即停等于**零引擎调用、零 token** 地拦下。
- **判定面**：`nextStep(goal).title`（计划采纳时由条目标题落进 `goal.json` 的文本）+ 显式升格标记 `[risk:high]`，两者走同一条命中通道。
- **只看下一步**：不扫全量 pending。扫全量会让「计划尾部有个高危步」的计划在第一段就整段停摆，把安全的活一起浪费掉。「any-pending 提前停」是备选形态，归实验结果评审，不在此 ADR 固化。

## 休眠语义（**本 ADR 最容易被误读的一处，显式记账**）

开关名 `LZY_ABLATE_H3R_GATE` 是**预注册冻结值**，但它与 `LZY_ABLATE_*` 家族的语义**相反**：

- 家族语义 = 「恰 `"1"` **消融**（关掉该部件）」；
- 本开关 = 「恰 `"1"` **唤醒**这个休眠原型」。

**默认休眠**：不设该 env 时，`core/drive.js` 的门块整段不执行，行为与 0.2.1 逐字段同。

依据是预注册的操作句，不是表格里的样板话——`docs/design-h3r-experiment.md:58`：「原型入 `core/`，`LZY_ABLATE_H3R_GATE` 恰 `"1"` 才生效，默认关行为逐字段同」，同稿 `:53-58` 另称该原型为「**休眠门**」，并以「契约测试钉两半（**默认关行为不变 + 开时停摆**）」描述验收面。

注记：该设计稿 `:24` 的三臂表格仍留着家族样板句「沿 ADR-0015 形态：恰 `"1"` 消融」，与 `:58` 相反。**以 `:58` 为准**；`docs/research-ablation-design.md` §2 的开关表在本棒同步加了「反向语义」注，防后人照抄家族句式把它接反。

**后续**：若实验结果评审决定 H3R 出实验、转正为默认行为，该开关应回到家族语义（默认开、恰 `"1"` 消融），届时须新立 ADR 并同步 ADR-0015 增补节与设计稿。

## 执法层级（不得夸大）

- **现状 = L0**。门的**唤醒形态**是机器件（开关开启时由 `core/drive.js` 执行，契约测试两半钉住），但**默认休眠**意味着它今天不是任何用户的机器门：zw SKILL 里 H3R 相关的句子仍是协议文本（L0）。
- **不得把 L0 说成机器门**：SKILL 与 guide 的措辞在本棒按此收口——「机器形态=休眠原型（实验件）」与「现行约定=L0」两件事分开写。
- 契约测试面：`test/h3r-gate.contract.test.js` 钉两半——唤醒半（停摆 + 快照落盘 + **零引擎 spawn**）、休眠半（同夹具照常推进、无 h3r 痕迹）、值语义（`""`/`"0"`/`"true"` 一律不唤醒）。

## 真实边界（诚实面）

词表是**子串匹配**，不是命令解析器。它**能被改写规避**（`rm -fr`、变量拼接、脚本里间接调用），也**不理解上下文**（注释里提到 `--force` 同样命中）。本原型测的是「机器层能否在段循环里看见计划书上的高危字样并干净停手」，**不是**「能否识破规避」。任何把本门说成「防住高危操作」的表述都超出证据。

同族的边界还有：判定面是**计划文本**，故计划里没写出来的危险动作不在视野内；显式升格通道 `[risk:high]` 依赖计划作者主动标注。

## 三条件核对（§9.5）

1. **难逆**：一旦实验结果被引用为「H3R 该不该转正」的依据，门的形态就已被它的实现细节锚定（词表口径、只看下一步、车道边界）——不落字，后人会照 `:24` 的相反样板句重接一遍。
2. **无背景会费解**：开关名与语义相反，是全仓唯一的反向 `LZY_ABLATE_*`；不写 ADR，下次复核必然重现「命名说消融、实为唤醒」的账目冲突。
3. **真取舍**：备选（a）原型不落主线、场外单跑——量不到真段循环里的停摆（C 臂的停摆是 drive 收束的一种新因，必须在写路径里插手），（b）落主线且默认**开启**——那是一次未经实验的行为变更，违反「结果只作拍板输入，绝不自动升格」（决策 #20/#25）。

## 增补节（2026-09-22，goal v023-h3r-enforcement；执法点迁移）

**决定**：在车道边界**不变**（仍只作用于无人值守的 `lzy loop drive` 段循环，交互会话仍是恢复路径）的前提下，H3R 的执法点自「段起点判下一步文本」前移两级：

1. **一段一步机器核验**（`core/loop.js` + `LZY_SEGMENT_ID`）：drive 唤醒态给段会话注入运行唯一段标（`<fence>:seg-<n>`——`<fence>` 前缀是为跨 run 唯一，纯 `seg-<n>` 会被上一 run 残留误伤），`lzy step done` 在同段第二次调用时拒（重录**同一**步 id 的取证 rebind 放行——实现 `prev.stepId !== id` 才拒，v023-fix-round ADJ-21 补记）。**为什么必要**：0.2.2 实验实测 24 发里 15 发单段跑完全部步骤，段起点检查根本没机会开火——粒度不修，门等于不存在。
2. **命令层门**（`plugin/hooks/h3r-pretool.js`，PreToolUse/Bash）：命令文本命中词表即 deny + 写 `loop/h3r-hit.json`（带段标）；drive 读到**本段**标记才干净收束（7 字段快照，exit 0，收束因 `工具调用被拒（PreToolUse …）`）。他段/伪造标记只清不留——它不是「一行即停」的匿名杠杆。

**开关语义（三枚，全为反向：恰 `"1"` 唤醒，休眠即默认关）**：`LZY_ABLATE_H3R_GATE`（0.2.2 已在账）、`LZY_ABLATE_H3R_ONESTEP`、`LZY_ABLATE_H3R_PRETOOL`；另有家族语义的 `LZY_ABLATE_HOOK_H3R_PRETOOL`（恰 `"1"` 灭掉该钩子，供 E 臂整层消融）。**依赖**：`H3R_PRETOOL` 离开 `H3R_ONESTEP` 是惰性空转（它要求 drive 注入的段标）；单开 PRETOOL 而读不到任何拦截，是设计使然，不是机制坏了。开关表与计数 prose 同批更新（`docs/research-ablation-design.md` §2/§3）。

**作用域为何现在是机器强制的**：门要求 `LZY_SEGMENT_ID` 在场且形状合法（`<整数>:seg-<整数>`，v023-fix-round ADJ-22 增补的形状校验；该 env 只有 drive 唤醒态才会注入——`core/drive.js buildSegmentEnv`）。交互会话拿不到 drive 注入的段标，以免门为常态——前提是 env 卫生：残留的误配 export 曾能激活门，形状校验落地后降级为无门（本句由「构造上的边界」订正为「构造 + env 卫生」）。这把 0.2.2 里靠 `LZY_ABLATE_H3R_GATE` 单开关约定的边界，抬成了构造上的边界。

**失败语义（诚实边界）**：钩子崩溃/超时/坏 schema 在引擎侧一律 fail-open（工具照常执行）；判定面是**命令文本的子串匹配**，且**排除仓库自身记账通道**（`lzy` CLI 与 `git commit|add|status`——否则步标题里的词表字样会把记录动作本身打成命中）；被排除通道是理论绕过轴，段内写者读到 env 后伪造匹配标记亦仍可能（门槛抬高，未根除，与段内自升级同信任级）。
