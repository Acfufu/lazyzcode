# ADR-0024：用户批准目标边界，代理自主维护执行计划

日期：2026-09-23。状态：accepted（设计共识）；用户明确要求暂不实施，尚未替代现行运行规则。
关联：[访谈记录](../design-v030-agent-first.md)、[ADR-0018](0018-ups-exact-hash-human-gate.md)、[ADR-0016](0016-attempt-lineage-propagation.md)。

## 方向决策

用户选择：人批准需求、验收标准和授权边界；代理可在该边界内自主规划、调整、实现和验证，超出边界再请求人决定。
理由是实施路径会随现场事实变化，要求每次计划变化都重新批准会把常规工程判断交回给人；
人的控制应落在所要结果与允许采取的行动上。未选择继续逐版批准完整执行计划的方案。

## 需要保住的性质

执行计划的自主修改不能扩大权限、删除承诺或放宽验收。
本方向不撤销审批记录、计划世系、评审和证据的可追溯性，也不自动授予合并、发布或部署权限。

访谈 Q3 进一步确认：默认交付终点是可合并变更；项目可以明确授权合并主干，或上线并完成线上验证。
后一种授权须显式存在，不因代理具有自主修改执行计划的权限而产生。
Q8 锁定 B/C 为 0.3.0 的实际能力：至少实证一条自动合并链和一条 Web 发布及上线验证链，
复用项目既有工具，首版只承诺已经验证的链路；不将此理解为授权本次规划会话执行外部交付动作。

访谈 Q6 确认交互请求与已授权待办队列并存：人可一次批准多项工作，代理完成一项后接取下一项；
自行发现的问题只形成提案，未经授权不执行。这要求正式修订 ADR-0003 的只续现行目标限制，
但不自动改变宿主定时唤起的归属。本设计尚未在运行协议中替代 ADR-0003。

Q10 为连续工作加入累计授权预算：单次运行上限与队列总额度同时生效；跨任务、重启和重试持续计入，
额度耗尽后保存进度，须由用户追加授权才能继续。具体额度在使用时设定。

## 协议提案与定案条件

[完整方案](../plan-v030-agent-first.md) §3 定义需求契约、不可变身份、范围变化与撤回，
§5 定义队列与累计预算，§6 定义有限 B/C 交付，§8 定义旧记录迁移。
积分硬顶能否兑现仍须经 M0 探针确认；事后记账不能代替已批准的上限语义。
用户已确认完整方案并要求交接另一会话；受影响的现行 ADR 随对应实现修订，本设计尚不 supersede 现行运行规则。
