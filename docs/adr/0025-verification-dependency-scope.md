# ADR-0025：按验证依赖决定证据失效

日期：2026-09-23。状态：accepted（设计共识）；用户明确要求暂不实施，尚未替代现行运行规则。
关联：[访谈记录](../design-v030-agent-first.md)、[ADR-0013](0013-integrity-kernel.md)、[ADR-0014](0014-invalidation-dag-red-green-manifest.md)。

## 方向决策

用户选择按验证依赖决定失效：证据绑定被测产物、验证程序与相关依赖；只重跑受影响检查。
依赖范围无法可靠界定时回退全量验证，合并后的最终产物仍须实际验证。
没有选择继续让任意提交一律作废全部证据的方案。

这是效率与依赖完整性之间的真实取舍：全树绑定简单、保守，但无关变化会引发重复取证；
范围绑定允许复用，却可能因遗漏依赖错误接受旧结果，不能只凭代理判断“应该无关”。

## 设计与验证要求

- 必须能解释每项证据依赖什么、为什么可以复用、哪些变化使其失效。
- 验证程序、构建或依赖配置变化不能因不属于生产源码而被忽略。
- 缺失、损坏或无法解释的依赖信息不得产生新的放行路径；保守回退应可观察和测试。
- 合并后的实际结果必须得到验证；仅更新指纹或记录新证据文本不等于执行过验证。
- 默认 A 的被测结果是工人变更整合后的交付候选版本，不要求提前合入主干；B/C 才追加已授权交付阶段的检查。
- 依赖遗漏导致错误复用须有对抗用例；三类项目的依赖边界与保守回退都要实证。

## 协议提案与定案条件

[完整方案](../plan-v030-agent-first.md) §4 定义执行回执、默认全树档、经验证的范围档、
环境及未知输入回退和候选整合验证；§6 定义 B/C 实际产物验证，§8 定义旧证据迁移。
具体配方必须通过依赖遗漏反例才可启用范围复用。本设计不直接修改 ADR-0013 的现行有效性规则，
也不授权通过重新标记旧记录来声称已完成新的验证。
