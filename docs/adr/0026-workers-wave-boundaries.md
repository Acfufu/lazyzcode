# ADR-0026 · workers 波编排的车道边界（收束相完整性、重锚语义、认领与回收所有权）

日期：2026-09-23 · 状态：已接受 · 来源：goal `v024-fix-round`（v024 五轮双审 39 条中发现 9 条落在 workers 弧）+ ADR-0020/0022 的既有边界

## 决定

`lzy loop drive --workers N`（0.2.4 收口窗口保留的实验形态，拍板见 `docs/reviews/2026-fast-exp-report.md` §4）在四个面上定死边界。四条都是**fail-closed 方向**：判不了就不做，做了就必须能看见。

1. **HEAVY 目标不得进入 workers 车道（入口硬拒，无逃生 flag）**。每波屏障重锚必换现行锚定绿，而 HEAVY finish 机器强制「对照 attestation 绑定现行锚定绿且指纹相符」——两条规则相乘即结构性死端：finish 必拒，预算却已烧完。入口 `LoopError` 指路「用单工人 `lzy loop drive`，或在交互会话推进」（tier 只升不降，无降档出口）。LIGHT × workers 仍可用（无对照门）。
2. **屏障重锚 = 指纹重锚，不是复验；且只在头树集实变时执行**。诚实边界写在证据文本里（`未复跑断言`）。**升格条件（预注册）**：若工人侧真复跑面立项（工人在合并树上重跑 F 项断言），本边界随之撤销——在此之前，把重锚说成「复验」即为假证据陈述。重锚须**原样透传**原绿的 `harnessSpec`（否则新绿无 `harnessHash`，INV-08 双在场判据恒假 = 机器门被自家编排无声拆除），读图失败 fail-closed（不静默降级为无 harness 重锚）。
3. **步级认领的所有权按 run 划分**。调度器在波终释放「本 run 期间写下（`claim.at ≥ runStartedAt`）且未 done」的认领——工人中途退场不留 48h 互斥饿死分派池；`runStartedAt` 之前的认领（交互会话/他人）一律不动。收束快照的风险节必须给出 `--release` 指路（认领既不在推进签名里也不在剩余步骤清单的语义内）。
4. **回收与清理的删除授权 = 属主哨兵 `.lzy-run.json`**（本 run 创建 runDir 时原子写）。形符（`^fast-\d{14}(-\d+)?$`）本身不构成所有权：名不符者、归档 `.logs`、形符而无哨兵者一律跳过并在日志点名。含未提交内容的 runDir 整体保留（保留物在 runDir 之下，父目录不能删）。清理相在**租约内**执行（摘 subject 是经 CLI 的带 fence 写命令，释放后被 `guardFence` 拒）、**先摘 subject 再删树**（否则悬空根使此后每次 finish 被完整性闸门恒拒）、脏 worktree 连同分支保留并在快照点名。

## 边界与已知代价

- **收束相不追 worktree 的未提交内容进宿主**：保留 = 留在原位并点名，不做 stash/搬运（搬运会造出第二份真相）。恢复靠人读快照。
- **重锚的 harness 透传依赖账本可读**：账本损坏时重锚前置读 fail-closed 收束（`屏障重锚前置读失败`），而非静默写出无 harness 的新绿。
- **一条波内多工人对同一 F 项的取证仍会互相换代**（fast-exp 报告 §1.3 的「1 次 supersede + 1 次屏障 rebind」级联），成本实测极小，不作为反对理由。
- **跨秒 runId 撞名的理论边界**：同进程同秒重入仍会撞（lease 单运行时互斥先挡住该形态）；跨进程由 `-<pid>` 后缀消解。

## 与既有 ADR 的关系

- **ADR-0020**（runtime kernel）：租约/fence/预算三门在 workers 径逐字段同源，本件不新开授权面，只把清理相移入租约窗口并修正记账相位（`recordSpend` 在 merge 之后——预算尽时本波产出已落宿主，不再脱账）。
- **ADR-0022**（H3R 车道边界）：workers 与 H3R 唤醒态互斥的既有规则不变；本件在清理/回收面无涉。
- **ADR-0013 / 0014**（完整性内核 / 失效 DAG）：本件的 subject 摘除与重锚口径是这两件在 workers 车道上的**执行细则**，判据本身不动。
- **决策 #30**：本件不改变 H3R 的去留状态（仍休眠、仍 L0），只在对抗清单债 H 的行内扩充词法绕过族的记账。
