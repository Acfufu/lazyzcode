# ADR-0031：由 lzy 承载独立评审执行过程

日期：2026-09-26。状态：设计决策与整体计划已确认，待实施；本轮不执行。

0.4.0 选择“机器闭环＋同期评估”，契约任务交付 A 均须独立评审，LIGHT 也不豁免。为使评审的启动、候选身份、原始结果、预算与中断结局可关联，采用 `lzy` 发起独立会话并收集结果的受控评审执行方式，复用已有 headless 原语；不采用主代理派发后仅导入结论文件作为必需评审的完成依据。后者更轻，但在当前宿主接线下尚缺可核验的来源与生命周期记录。

首轮共享契约、项目规则、候选及必要证据，不提供其他评审结论。评审消耗进入原任务预算，执行失败不构成通过；隔离、采集、计量及中断能力必须在首个里程碑实测，未证实则保留阻塞，不暗中改用自报。该选择仅建立必需评审的执行闭环，不扩为通用多代理调度平台。

来源可追溯不等于判断正确或安全沙箱：同权限进程仍可篡改本地材料，评审效果与成本须接受同期独立评估。结果复用见 ADR-0032；旧任务兼容与显式迁移按已确认主计划 §7 执行。

阻塞发现的关闭权（同日 Q5 确认）：实现代理只能标记修复待复核；独立复核者根据原发现、修复与当前候选证据确认关闭，不要求是原评审会话。误报也须独立证伪，原记录与处置历史保留；后轮遗漏、改名或仅有测试通过不能关闭。这增加复核成本，以防实现者与测试共享误解或通过重跑评审抹去阻塞发现。
