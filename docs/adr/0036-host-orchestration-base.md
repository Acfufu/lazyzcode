# ADR-0036：宿主底座分界与执行图调度（2026-10-01）

宿主 ZCode 的 dynamic-workflows 引擎（TS 脚本编排子代理、typed 中间结果、run journal、SendMessage、artifacts 观察面）是**编排基础设施底座**；lzy 不重建、不桥接、不感知其过程面，四象限缺口（执行图编排/团队对话/节点通信/外部观察）一律重写为「宿主原语之上缺什么纪律」。分界依据：证据绑 tree hash 的现行设计天然覆盖任何执行者（含 workflow 子代理）——**过程归宿主，成果归 lzy**；对照报告判词「lzy 的差异化在审计与交付的严谨度，不在规模与编排宽度」，mass-ulw 式产品级并行编排/wire 协议不追平（触发器化挂债）。lzy 在执行图上取的是**纪律**：中央图调度器=单源图核心（deps 语义唯一权威）+三执法点——①计划门 deps 健全性执法**单源化**：validateDeps（core/loop.js:686，采纳路径 :1245 调用）与就绪谓词迁入 graph.js、接线保持——校验已存在且有三例契约测试背书（悬空/自指/成环），真缺口=drive.js 手抄副本与无单源核心（勘误注记：grill 初盘「现行零校验」系误核——核了统一门 gate.js 而非 loop.js 计划采纳路径，plan-reviewer 实测抓正）；②claim 就绪集改吃单源（删 `core/drive.js:680 blockedByLocal` 手抄副本，ADJ-39「一个谓词多处复制必漂移」家法）；③drive 波分派由轮转均分升关键路径优先（仍在 `--workers` 实验车道内，B2 判据①灰带终拍不翻案）。**认领互斥层（claim 48h）语义不变**：调度器管就绪与顺序，认领管归属。被否的替代：步↔workflow run 绑定（workflow 无引擎 CLI 面、需新增第 6 处引擎契约面、与「证据绑树不绑人」纯度相悖）；调度器拥有派发（grant 账本与认领职责重叠、多会话机器面全部重过）。观察层配合见决策 #46（图视图同读执行图与失效 DAG——「跑的过程与做的证据接在同一张图」在观察层达成，存储层两图分立）。
