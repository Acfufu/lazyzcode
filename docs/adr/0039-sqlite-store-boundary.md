# ADR-0039：局部状态 SQLite 存储边界与最低运行时地板（2026-10-16）

**拍板**：工作区局部状态（队列条目/派发事务与分段/预算事件账/批次预算设置）迁入**单库 `.lazyzcode/state.sqlite`**（内建 `node:sqlite`，零新增依赖），goal/DAG/runtime/授权/证据/转录保留文件与语义；**最低运行时地板＝Node ≥24.0.0**（用户拍板 2026-10-16）——22 线不入支持面，理由=实测能力矩阵：22.12 及以下无 `node:sqlite` 模块；22.13 起模块可用但构造器 `{timeout}` 被**静默忽略**（跨版本行为面不可靠）、每次进程加载打一条 experimental 告警；24.0.0 地板全探针通过（24.19.0 起告警消失，如实记档）。据此冻结**操作纪律＝只用 SQL 层**（`PRAGMA journal_mode`/`busy_timeout`/`integrity_check`、`VACUUM INTO`、纯 SQL 事务）；构造器唯一例外＝`{readOnly:true}`（经探针矩阵验证：只读打开成功、写尝试必败）；其余构造器选项与高阶 API 不用。**切换姿态=前向单向**：显式迁移（`update/sync` 永不自动迁移）、迁移提交点沿 ADR-0029「最后写=提交点」先例（journal+备份→导入临时库→逐项对账→原子安装→backend 标记最后写）、切换后 DB 唯一权威（不可读不回落到旧 JSON）、不提供反向导出并明示不支持自动回退；打开即 WAL 回读校验（≠wal 拒启不静默降级）、备份= `VACUUM INTO`+`integrity_check`、不复制主文件冒充 WAL 快照。engines 字段与安装文案的机制收紧随 P3 切换窗口落地（切换前 JSON 面现行 ≥22 全额可用，不做虚假收窄；DB 面由运行时能力探针拒启具名诊断）。被否替代：`better-sqlite3` 等原生依赖（破零依赖+平台预编译矩阵）；地板 ≥22.13.0（22 线构造器选项差异与告警面把「跨版本可靠」建立在未穷举行为上）；维持多文件 JSON（跨 queue/dispatch/ledger 无统一事务=迁移动机本体）。P1 批据此完成存储契约冻结与隔离五面试点（唯一事件约束/占用事务/结算事务/并发冲突/崩溃恢复）；实施依据=`docs/design-sqlite-store.md`（schema 定案/语义对账表/锁序/迁移协议全文），批次与验收=`docs/plan-lzy-sqlite-state.md` §4。
