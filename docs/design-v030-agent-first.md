## Q1 的含义

- 规划应覆盖从需求到交付反馈的完整体验，不能只增加执行角色或门禁。
- ZCode 是本轮执行底座；借鉴其他团队的工程方法不意味着迁移到它们的产品或 SDK。
- 旧流程设计可评估替换；现有硬约束、权限和产品契约在形成明确修订前仍按原规则执行。
- “完整”描述最终工作流的覆盖面；本版范围、里程碑与发布验收仍待决定。

## Q2 的含义

- 区分用户承诺与实施路径：前者决定权限和成功条件，后者由代理在边界内维护。
- 代理不能通过改计划放宽验收或扩大授权；需要新增权限时重新请求用户决定。
- 此项要求重设计 ADR-0018 的批准对象与失效条件，不等于删除批准、评审或证据机制。
- 已写 [ADR-0024 草案](adr/0024-agent-first-approval-boundary.md)，整版规划收口时同步正式决策与 AGENTS；现有产品仍按 ADR-0018 执行。

## Q3 的含义

- 默认完成须有可审查、可验证的变更；代理不能把本地目标完成自动报告为已经合并或上线。
- 项目可明确授权更远终点；其授权如何持久化、如何撤回、怎样绑定具体环境，待协议设计决定。
- B/C 的本版交付范围已由 Q8 锁定为有限真实链路；具体项目、托管和部署环境的选择仍须落实。
- 已确认的交付概念写入根级 `CONTEXT.md`（仓根非站点页）；实现字段、状态机和兼容策略不进入术语表。

## Q4 的含义

- 三类都是必须验收的能力面，不只用示例 CLI 或空白 Web 项目宣告整套工作流完成。
- 需在真实存量项目观察环境准备、实现、实际使用验证和中断恢复；具体任务集在验收设计阶段冻结。
- 本轮已通过 App 项目清单确认 lazyzcode 与 zpigeon-ios 均为可用 Git 项目；后者是原生 App 候选，尚未选定具体任务。
- 技术栈差异应由项目已有工具和验证入口承载；三类覆盖不等于承诺支持每种框架。

## Q5 的含义

- 保留正确性与可追溯性资产，不把现有模块边界、命令命名或字段布局当作必须维持的约束。
- 历史证据保留不等于自动获得新协议的有效性或交付权限；迁移必须明确各类旧记录的含义。
- 需要定义旧版已完成目标、在途目标与批准记录的迁移行为，以及失败恢复；本轮尚未选择自动迁移或显式迁移命令。
- 迁移工作属于 0.3.0 的交付范围，不能留给用户手工编辑内部账本。

## Q6 的含义

- 待办队列里的可执行项已获需求、验收与权限授权；仅有标题或代理发现的问题不等于可执行授权。
- 完成一项后可以启动下一已授权项。现行 ADR-0003/zw 的“只续 executing、绝不立新目标”需要正式修订。
- 此项决定取哪些工作，不决定定时唤起由谁负责；不据此引入常驻守护进程或代写宿主自动化配置。
- 队列优先级、依赖、取消、批准失效、预算耗尽和失败后是否跳过等规则，纳入后续协议设计。
- 自主发现可记录为提案供用户选择，不自行扩大当前目标或消耗其执行授权。

## Q7 的含义

- 从一律全树过期演进到可审计的依赖范围；被测产物、验证程序及相关依赖共同影响证据适用性。
- 范围完整性没有可信依据时保守全量验证，不能以人工或模型的主观“无关”判定直接复用。
- 合并后的最终产物要真实验证；更新指纹或账本记录不是一次新的验证执行。
- 此处包括工人变更整合后的候选版本；默认 A 验证该候选版本即可，不要求为完成验证擅自合入主干。选择 B/C 后再履行相应交付阶段的验证责任。
- 已写 [ADR-0025 草案](adr/0025-verification-dependency-scope.md)；依赖识别、保守回退和失败反例须先通过验证，再替换现行全树规则。

## Q8 的含义

- 0.3.0 的发布验收包含 A、B、C 三种终点；A 是默认，B/C 必须有明确项目授权。
- B 至少有一条真实自动合并链；C 至少有一条真实 Web 发布与上线验证链，结果与证据必须可追溯。
- 首版复用项目现有工具，不承诺通用托管与部署平台适配矩阵。
- 需覆盖外部动作失败及结果不明确的处理；发布命令退出成功不能替代部署后实际验证。

## Q9 的含义

- CLI 基准项目为 lazyzcode，验证命令行为、状态迁移和中断恢复。
- Web 基准项目为 openchamber，验证浏览器交互、应用启动及前后端实际行为。
- 原生 App 基准项目为 zpigeon-ios，验证构建、模拟器操作与真实用户流程。
- 三仓选择已确认；具体任务和 B/C 外部交付目标由后续勘察形成方案，本次选择不代替实际外部操作的授权。

## Q10 的含义

- 总预算归属于一次队列授权，不能通过新建目标、重启运行或重试失败任务重置。
- 单次运行限额仍有效；预算耗尽保留进度，新的额度必须由用户追加授权。
- 计量口径、并发占用、崩溃恢复以及积分观测延迟的真实边界须由设计与探针明确，不把事后记账夸成严格实时计费控制。
