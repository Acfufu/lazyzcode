## 接手后的第一份回复应包含什么

1. 当前阶段是 P0，已读到的协议版本与源状态；有哪些未提交内容需要保留。
2. 本机能确定的事实：宿主/引擎版本、实际模型与计价可见性、隔离能力、候选来源、可用计时/归账工具。凭据只验证存在与可用，不输出秘密。
3. 可免费继续的工作，以及付费/用户参与前真正缺少的条件。缺少条件不是实验失败，但不能把它写成已通过。
4. 最小工作清单与下一份可验收产物；若要修代码，列具体文件责任与验证，不能顺手实现整个 0.5.0。

## 阶段交接与继续规则

- P0/P1 的准备报告、缺口和免费检查可由 ZCode 自主完成。涉及用户参与、不同模型计价、额外付费开发或尚未授权的动作时，提交具体缺项，不猜授权。
- P2 冻结后，实际用户运行必须等待用户可参与的时段；不能把机器执行时间当成人工时间。
- 主对照要在没有 lzy 指令污染的新会话与隔离环境中运行；不要直接在这个带有全部产品说明的协调会话里执行对照题。
- 费用达到停止阈值、未结算用量、关键身份漂移、隐藏信息泄露或疑似严重错误时，按协议停止对应派发，保留现场与所有费用。
- 用户验收属于被测交付；独立实验复核属于研究工作。产品内评审费用归任务账，不得偷放进外部验收账使候选显得便宜。
- 每次声称完成或提交用户验收都保留当时的产物快照、哈希、原话和公开验收结果；疑似严重错误先暂停复核，后续修复不抹去已经确认的错误交付。
- 收齐材料后交独立会话复核。缺复核就报告待复核，不生成虚构的签字、PASS 或已采纳结论。
