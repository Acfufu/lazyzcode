# 下一步迭代：验证 LazyZCode 的完整产品价值

日期：2026-10-11。状态：用户已确认规划方向并要求落文档；**本次仅授权出计划，未启动实现、模型探针或付费实验**。不指定下一版本号，不替代历史预注册，不修改默认行为与现行 ADR。

## 1. 要回答的问题与停止条件

在中等复杂度、多文件、无人值守且可独立验证的本地编码任务中，完整安装并启用 LazyZCode，相对原生 ZCode，能否带来更多正确交付或更少假完成，同时每次正确交付的成本不增加？

结论服务于产品是否值得默认推荐，仅适用于实际测试的引擎、模型、工具环境和任务范围。它不等于内部旧策略默认切换，不自动授权发布、推送、合并、部署或修改用户配置。

执行顺序：**M0 测量与能力核验 → M1 小规模诊断 → M2 条件式修复 → M3 独立正式评估 → M4 结论与交接**。没有可靠修复原因时可跳过 M2；预算不够时允许停在“证据不足”。到达阶段验收或预算停止条件即停止，不持续加跑以追求预定结论。

## 2. 已拍板的实验契约

| 项 | 固定选择 |
| --- | --- |
| 产品对象 | 原生 ZCode vs 完整 LazyZCode；不以 0.4.1 vs 0.5.0 代替 |
| 主要收益 | 正确交付增加，或假完成减少；两者均记录，不用诚实停止冒充交付 |
| 任务范围 | 中等复杂度、多文件、本地独立可验；开发覆盖 CLI、Web、iOS |
| 公平条件 | 两臂同可见要求、验收标准、通用计划/自检/诚实报告要求；原生臂保留正常工具与自检能力 |
| 验收隔离 | 密封 oracle 不提供给执行者；可见验收要求不隐瞒；判读器独立于产品完成状态 |
| 正确交付 | 独立验收通过，且在预算内明确交付；正确但未交付、具名诚实停止均不计成功 |
| 成本口径 | 所有实际尝试、失败、重试、子代理、独立评审均计入；每次正确交付的单位成本不得上升 |
| 实际收益门槛 | 正确交付率至少提高 10 个百分点，或假完成率至少降低 10 个百分点；另一质量轴不得下降，关键假完成为零 |
| 统计证据 | 正式批须跨独立任务、有配对重复并预注册不确定性分析；点估计达到 10pp 不足以采纳 |
| 开发运行额度 | 最多三对、六次；每次全链路 45 分钟；名义总运行上限 4.5 小时 |
| 开发积分额度 | 六次及其全部链路共享 **100 估算积分**；不是每次 100，也不是官方订阅余额 |
| 开发结论 | 只诊断、估算成本与正式设计；三对不能证明收益或支持默认推荐 |
| 正式预算 | 根据开发实耗另行冻结；未冻结不启动，无法辨别效果则证据不足 |
| 历史关系 | 保留 ADR-0034、#49、旧预注册和负结论；本轮独立预注册，不直接移植旧版本比较门 |

这份计划本身不启动上述运行额度。模型探针、实施、开发运行和正式批执行均不因落文档自动获得启动授权。

## 3. 架构边界与证据等级

来源：[当前差距研究](research-current-omo-lazycodex-gaps.md)、[宿主编排 ADR-0036](adr/0036-host-orchestration-base.md)、[文书协议 ADR-0035](adr/0035-document-protocol.md)。

- **ZCode 负责**：代理执行、模型运行时与限流、动态工作流、进程恢复、工具注册、浏览器/模拟器、记忆存储与检索。
- **LazyZCode 负责**：计划与义务、授权、认领和依赖纪律、证据现行性、独立评审、成本记录、完成或诚实停止；按诊断需要补技能指引与能力检查。
- 本轮不新增调度器、自由消息协议、模型路由或记忆运行时；不重开 H3R、fast 默认化、HEAVY workers、watch/HTTP/wire/viewer、非 Git finish 等休眠议题。
- 永不改写用户 config.json；Stop 与后台通知共享池的现行预留保持。OmO 主仓只研究思想和能力；可借用 LazyCodex MIT 资产时标注出处，遵守本仓素材边界。

能力表逐项区分：**源码存在／随包提供／已启用／目标会话暴露／真实行为已验证**。当前研究锚点为 ZCode 壳 3.15.1、引擎 0.16.9，执行前重新核定；只核版本不足以证明插件 JSON、工具或策略兼容。

`CreateWorkflow` 仅在用户明确指定 workflow 作为手段时调用。普通任务不得通过额外提示偷偷开启；若任务明确要求，两臂使用相同指令且限定结论范围。技能接线不得绕过触发条件。

## 4. M0：修好测量边界，建立能力清单

### 工作与位置

优先检查 [run-pairs](../scripts/evaluation/run-pairs.mjs)、[headless](../core/headless.js)、[cost](../core/cost.js)、[review](../core/review.js)，先写失败检查，再做最小修复。原评估器和历史批应保持可重判、可追溯；新实验身份与旧批分开。

1. **明确两臂身份。** 原生臂没有 LazyZCode 载荷或本仓纪律注入；产品臂实际安装、启用并留装载凭据。不能只根据设置路径推定加载或未加载。两臂保留相同的通用 AGENTS、工具权限、宿主插件与可见任务信息，隔离实验专用 HOME/工作树；不得夹带本仓产品宪法进入原生臂。
2. **公平提示和真实授权。** 共同提示要求计划、自检、诚实说明和交付记录，不要求原生臂执行 lzy 命令。产品臂遵守完整产品契约，不设人权门消融；采用产品支持的真实预授权或运行前审批路径，冻结授权对象与条件。若无人值守仍需人工输入且没有合法解决路径，则记准备阻塞，不绕门。
3. **共同结果协议。** 两臂使用中立交付记录，绑定受验源码状态、明确交付时间、验证说明和停止原因。独立验收读取受测状态；lzy goal done 只是产品内证据，不是共同判定器。将未生成交付记录与声明内容明确矛盾分开记录。
4. **全链路账本。** 主会话、子代理、独立评审隔离 HOME、失败、重试和被后续尝试替换的运行全部归属于 batch/pair/arm/attempt。去重用真实用量身份；重判不算新消耗，真重跑不能抹掉旧成本。缺失与未计价保留未知、tokens 和已知下界，不合计成零。
5. **全链截止。** 共用启动时间与截止时刻；截止后停止新的派发，回收本次运行所属后代和评审，不影响无关进程。不能用父进程返回证明消耗停止。积分逐段完成后检测、停止下一派发，在途超额和远端滞后落账如实记录；不承诺精确硬切积分。
6. **能力核验。** 记录版本、插件输出形状、模型/provider、Agent 与工作流触发条件、QA 表面、LSP/CodeGraph 等实际环境。无模型调用的检查先做；模型探针若后续获准，必须明确占用六次中的哪个名额，披露少跑诊断任务的影响，不增设免费或额外额度。

### 验收与停止

- 新实验 manifest 能拒绝身份混杂、缺臂、重复身份、未知判读和不完整计量；不能输出采纳通过。
- 离线 fixtures 覆盖正确交付、假完成、正确未交付、错误未交付、诚实停止、超时、缺账、重试与重复落账；验收正/负 canary 双向正确。
- 聚焦回归失败于缺陷版本、修复后通过；可参考既有 [evaluation runner](../test/evaluation-runner.contract.test.js)、[qualification](../test/evaluation-qualification.contract.test.js)、[headless](../test/headless-primitive.contract.test.js)、[cost](../test/cost.contract.test.js) 测试，按实际改动选择检查。
- 用本地测试进程树验证截止、评审终止与回收，不需要模型调用。真实模型、装载和授权行为在后续批准运行中取证；未证项明确保留。
- 任何公平性、授权、共同判读、成本归因或停止边界无法满足，停止 M1 派发，输出阻塞与最小解决路径。

交付：能力清单、两臂环境与提示契约、新结果/成本 schema、离线验证记录、M1 准备清单；记录源码 hash、包 hash 与精确检查命令。此阶段不要求构建通用观测平台。

## 5. M1：三仓诊断，不作采纳

依赖：M0 工程验收完成、准备项已核实或能在首次运行中安全留证；启动授权已明确；预算账本和停止规则生效。

- CLI/Web/iOS 各一个开发任务、各一对，共最多六次。可选仓库延续现有三仓覆盖，但任务清单、起点和可用 QA 环境须冻结；不读取密封正式任务。
- 同一对使用相同任务起点、主模型/provider、宿主版本、工具、权限、可见标准、时间与积分规则；允许产品自身引发不同子代理或评审消耗，全部计量并披露。
- 冻结任务顺序及两臂先后，记录随机种子；使用隔离工作树避免前一臂改变后一臂输入。六次额度用完不得自动加跑。
- 同时检测每次 45 分钟截止和开发全批 100 估算积分帽；任一触发停止后续派发。未完成配对、消耗不完整、在途超额保留，不用替换成功样本掩盖。
- 结果按“验收通过/失败/未知 × 交付/未交付”记录，再标注合法诚实停止、预算耗尽、关键错误等原因。成本是全尝试累计；零正确交付时单位交付成本不可定义，不写零。
- 归因类别：宿主执行/工具、规划与技能使用、真实 QA、授权与完成纪律、上下文/续跑、计量/判读。区分日志支持的因果、可复现假设和未知。

验收：运行与未运行项可核；每次都有结果、完整成本或明确缺口、源码身份与停机记录；形成最小修复建议和正式批资源估算。无论六次是否跑齐，都不能据此宣布产品收益或默认推荐。

交付：开发 manifest、全部尝试与用量日志、逐对四格结果、失败归因、成本完整性表、M2 候选及 M3 设计输入。日志可能含敏感信息，默认保留本地；公开报告只引用必要的脱敏证据。

## 6. M2：只修因果已确认的问题

依赖：M1 中观察到具体问题，并通过源码、离线回放或聚焦红绿验证建立因果证据。一次真实失败有充分复现即可，不要求额外付费重复出现。

优先顺序：测量与成本错误 → 授权/完成路径摩擦 → 技能触发与工具指引 → 有证据的 QA/交接问题。对宿主缺能力，先给出兼容限制或可用原生路径；不以 lzy 自建运行时兜底。

每个增量写明触发、前后行为、最小改动、红绿检查和真实表面验证。不得弱化义务、发现门、授权或证据条件，不以减少完成声明掩盖错误；已有机制没执行时先查接线和代价，避免叠加同类制度。

额外模型调用、优化后付费复测不在六次之外默许；额度耗尽后必须另行冻结预算并取得启动授权。没有可靠问题则跳过。本阶段通过后冻结候选源码、插件包与环境，后续变化须刷新受影响证据。

交付：因果诊断、变更与验证记录、候选冻结 manifest。实质决策变更遵循 ADR、decisions、AGENTS 同步规则；现有债账未满足触发条件不重开。

## 7. M3：独立正式评估，先预注册再运行

依赖：M0 验收、M1 资源估算、M2 候选冻结或明确跳过。正式任务必须全新、独立准备与封存，不从原生失败列表挑选，不把开发任务当独立正式样本；重复同一任务只增加 trial，不增加独立任务数。

正式运行前一次性冻结：

1. 任务抽样范围、独立任务数、配对 trial 数、顺序与 seed；样本量依据任务异质性、开发成本和可分辨效果，不事后调数。
2. 可见要求与密封验收、共同交付协议、关键假完成定义、结果分母、判读盲法与争议处理。
3. 两个收益分支：正确交付率提高至少 10pp，或假完成率下降至少 10pp；另一质量轴不劣、关键假完成为零。假完成主率以全部冻结运行作分母，并补报声明完成中的错误比例，避免因少声明而制造收益。
4. 配对与任务聚类的不确定性分析、两个备选分支的选择/多重比较处理、另一轴不劣的证据规则、成本比较与缺失规则。点估计须达到实际收益门槛，预注册分析须支持方向；不得事后放宽不劣界限。预算不足以辨别方向则判证据不足。
5. 正式运行、评审、canary、恢复与重跑的全部墙钟/积分额度，以及派发、截止、失效样本、预算中断与分母处理；任一不可判项不能默认算通过。重跑原因、替换规则和所有成本保留。
6. 两臂身份、实际插件装载、授权、主模型/provider、宿主工具与版本、候选源码和包 hash。环境变代或候选变化须按冻结规则暂停/失效，不能混批求结论。

单位正确交付成本使用每臂全部实际消耗除以正确交付数；必须有完整计量且产品臂不升。正确交付为零或成本无法完整对账时，不得宣称成本门通过。正式实验中包括两臂总耗费，产品单臂成本是结果指标，两者不混用。

M3 只比较原生与完整产品，不新增 OmO/LazyCodex 付费实验臂。实现者不得接触密封任务；看过正式任务再调参，该批不能继续充当独立检验。满足冻结批终点或任一预算停条件即收束，不持续追加样本。

交付：新预注册、独立任务 manifest、候选冻结凭据、所有运行/尝试/成本账、独立判读、配对分析和限制说明。

## 8. M4：三种结论，推荐与默认切换分开

| 结论 | 条件与后续 |
| --- | --- |
| 支持有范围的产品推荐 | 有效正式批满足收益、另一轴不劣、关键错误零与单位成本门；明确引擎/模型/任务/工具范围，形成推荐提案 |
| 未达到 | 数据完整且可判，正式预注册条件未满足；保留负结论与原因，不事后降门 |
| 证据不足 | 预算不足、样本不足、计量缺口、身份混杂、独立性破坏或不确定性不能支持方向；说明缺少什么，不包装为无效或成功 |

历史 [ADR-0034](adr/0034-strategy-adoption-deferred.md)、[0.5.0 报告](spikes/v050-m3-report.md)、[旧预注册](../scripts/evaluation/PREREGISTRATION-v050.md) 保留。新产品推荐即使获得支持，也不替代内部旧策略默认切换门。实际默认行为变更、提交、推送、发布或部署另依授权与发布检查表，不属于本计划落盘。

交付：独立评估报告、产品建议、范围与风险、剩余阻塞和可执行交接。不得凭架构丰富程度、角色数量或技能文字宣称质量提升。

## 9. 阶段依赖与当前待定项

| 阶段 | 启动条件 | 出口 |
| --- | --- | --- |
| M0 | 实施启动授权；先读实现与适用说明 | 工程测量可信、准备清单明确；不能满足则停 |
| M1 | M0 + 开发实验启动授权 + 冻结六次/总预算 | 诊断和资源估算；额度触发允许不完整收束 |
| M2 | 因果确认；额外付费另授权 | 最小修复验证与候选冻结，或明确跳过 |
| M3 | 新任务独立封存 + 完整预注册 + 正式预算/启动授权 | 有效正式结果或具名不足；不自动追加 |
| M4 | 独立判读与账本可审 | 支持、未达到或证据不足；交接后停止 |

现在不需要补选产品方向。执行时待定：开发具体任务和顺序、合法预授权路径、正式样本/检验方法/额度。前两项在 M0/M1 冻结，正式设计在 M1 后确定；无法满足既定方向时才带证据提出取舍，不提前编造数字。
