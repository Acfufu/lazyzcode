## 3. 执行策略与义务

### 3.1 策略身份与输入

首版采用随载荷发布的少量配置与普通判定函数。记录 `policyVersion`、规则内容哈希、契约哈希、项目清单哈希、任务身份、候选及影响事实；任务运行期间固定策略版本。新版本只能作为采纳提案，不自动替换在途策略。

输入为契约验收及边界、已批准的项目能力、实际变更、现有 tier/risk 和已知风险事实；模型可补充风险理由，不能用分类结论代替事实或删除底线。影响清单至少覆盖源码、检查程序、锁文件、共享配置、构建入口、环境输入、跨 subject 依赖及外部副作用；无法分类时保守增加核对，不凭文件数量降风险。

输出为带稳定 id 的策略义务：类型（检查/评审/CI/交付核对）、来源、适用理由、验收映射、满足条件、依赖边界与版本。每项都能回答“为什么需要、由什么结果满足、何时失效”。契约与现行分级决定的底线不可撤销。

首版评审职责为通用正确性必选，按事实追加权限与外部副作用、状态与恢复、验证依赖三类专项；这是职责集合，不是固定四个会话。一个独立运行可覆盖明确兼容的职责，但不能自审其实施或修复。职责未覆盖或未知影响未处置即不满足放行。

### 3.2 策略变化

影响扩大追加义务，记录前后差异。额外义务因影响消失而取消，须独立复判并保留原义务、变化事实、理由与运行依据；实现者不能直接删项。契约验收、现行分级强制要求和未解决阻塞发现不能经此通道取消。复用只满足现存义务，不能隐式减少义务。

任何需求、验收、权限、交付终点或预算变更仍走原契约/授权路径，策略记录不形成新授权。依据 [ADR-0033](adr/0033-policy-obligation-reassessment.md)。

## 4. 受控评审与发现闭环

### 4.1 运行协议

复用 `core/headless.js spawnHeadless`，实现受控评审执行器。每次启动前固定契约、策略、候选和输入包；记录 runId、职责及版本、会话标识、模型/引擎/提示模板身份、开始结束、退出、原始输出及摘要哈希。有效结果由真实运行采集，外部导入报告可作参考，但不能单独满足必需评审。

执行器显式选模式；不依赖当前引擎不支持的 `--max-turns` 或模型旗标。首版职责运行串行，降低预算与恢复复杂度；复用同一原语而非引入通用调度器。启动前查授权和余额，消耗按原任务及 sessionId 去重，墙钟不因父子运行覆盖同一时间段而双扣；计量缺席、未计价、在途死亡按现行“不算零”处理。

首轮输入共享契约、项目规则、必要代码与证据，不提供其他首轮结论。评审输入与实现会话历史分离，封存各首轮原始输出后才汇总；独立复核则必须提供被复核的原发现与修复事实。M0 验证 HOME/profile/记忆和工具读取路径，植入结论泄露探针；不能只因启动新进程就宣称隔离有效。污染、输入不完整、运行期间候选变化、结构化结果解析失败均不可通过。

评审读取固定候选快照；输入与工具边界在能力探针中验证，执行前后核对产物未被修改。该约束不宣称能抵御同权限恶意进程。必要上下文被隔离措施误删也属于无效运行，不能以少看代码换“独立”。依据 [ADR-0031](adr/0031-controlled-independent-review.md)。

### 4.2 发现身份与处置

发现记录绑定任务、职责、原运行与候选，至少含定位、触发条件、影响、依据、严重度和阻塞理由；不以发现数量投票。首版状态为待核实、成立、修复待复核、已复核关闭、证伪、非阻塞延期，迁移事件只追加。

- P0/P1、违反契约验收、授权/预算/证据完整性或约定交付条件者阻塞；P2/P3 也可能因直接违反验收而阻塞。待核实的潜在阻塞保持阻塞直到独立裁决。
- 实现者可提交修复并标记待复核；独立运行确认修复或证伪后才能关闭。未再次报告、改标题、换角色、重新规划、重启或 reset 均不能消除未关闭发现。
- 去重保留原 id 与别名关系；根因关联由独立裁决确认，不用模糊相似度自动关闭。语义分歧由独立裁决者核对事实，不能多数票通过。
- 非阻塞项可按策略记理由延期，保留记录；阻塞项没有“延期即放行”的出口。改变契约承诺必须另走原批准路径。
- 同根因第二次修复失败触发诊断与计划假设复核，继续使用原授权预算；不以“再跑一轮未提及”收尾。预算耗尽或无法继续时记录未完成与交接，不自动报成功或要求用户批准代理能自行完成的普通修复。

## 5. 检查与评审适用性

沿用中央 DAG 与验证回执事实，不另建一套可独立修改的完成权威。原记录不可变；复用和取消均为追加判断。每次解释应包含原记录、原/当前候选、规则与依赖身份、变化清单、资格引用、决定和具名理由。

检查适用性与检查成功分别判断。失败回执可以作为历史事实保留，但不能因 `judgeReuse.ok` 为真而满足成功义务。契约不匹配、原始工件不可核验、检查程序/环境/清单变化时，不能伪造新回执；旧 null 契约绑定不得猜测补齐。

评审范围资格绑定职责定义、规则版本、输入边界及其资格程序，不能按整个仓库永久授予。M4 实现以下闭环：

1. 声明本职责依赖范围，纳入共享配置、检查依据、跨目录/跨 subject 及动态输入；模型提出范围只是候选声明。
2. 在隔离夹具执行资格挑战：范围内影响、范围外遗漏依赖、未知新增文件、重命名/删除、验证脚本、锁文件、环境、契约与职责变化；包含应失效与可保持两种对照。
3. 资格不能仅证明“哈希能检测已声明文件变化”；还须用范围外影响反例验证边界。有限挑战只授予该明确范围与版本的资格，不证明一般依赖完备。
4. 满足资格且当前变化完全可解释时追加适用性判断；新增未知路径、损坏声明、动态依赖无法界定、资格版本变化均回退重评。对不可界定职责保持整候选范围；首版仍必须在三仓各完成至少一种有效范围复用的正反例，不能全量回退后声称此能力已交付。
5. 阻塞发现的关闭依据同样随候选核对；影响修复或关闭依据的变化使其需重新复核，保留历史“曾关闭”事实。尚未关闭的发现不能通过复用报告洗掉。

不把安全评审、算法评审或全局正确性评审强行声明为局部范围。未知信息导致重评的成本纳入评估。依据 [ADR-0032](adr/0032-review-scope-reuse.md)。

## 6. 统一放行判定与外部事实

共同只读判定模块返回逐义务满足情况与阻塞原因，不启动模型或外部写入；执行器取得结果后再调用该判定。当前可交付 A 必须同时满足：

```text
当前契约与授权有效，策略身份有效
且契约验收映射完整，必需检查成功并适用于当前候选
且独立评审职责全部覆盖，原运行或复用依据有效
且没有未解决阻塞发现，关闭依据仍适用
且声明的必需 CI 覆盖当前候选并通过
且原有步骤、证据、comparator、干净树与竞态门通过
```

CI 使用明确的必需检查标识及来源，不能把“查到的几项全绿”代替完整集合。首版必需项仅 success 通过；neutral/skipped/cancelled/pending、零结果或查询失败均不冒充 success。没有远端 CI 时只报告本地已验证候选，不能报可合并变更；三仓正式 A 评估必须在 M0 准备真实对应 CI 与必要授权，不能用假 gh 结果补齐。该规则延续 0.3.0 主方案 §4.3，并修正现有不同 CLI 面的判读漂移。

接线必须覆盖 `finishLoop`（包括 done 重入）、queue 正常收口与 done 分支、reconcile 的完成追认、手动/队列 delivery 外发前。queue 恢复时不能只看旧 goal.status 或意图 done；也不能因旧目标已归档而任意 reset 新目标。候选在判定与写入完成状态之间改变则拒绝，沿用锁/fencing 与复采约束，不在状态锁内等待长评审。

B/C 仍各需显式授权，合并自动触发 Pages 时保持 B∧C 门。A 通过不授予 B/C。外部动作前检查当前候选；动作发生后保留其实际身份并取得针对 merge/deploy 产物的所需验证，不能用动作前结果冒充动作后验证。已经合并/部署的事实不回卷，读回优先，恢复不得盲目重发。本版复用 0.3.1 的交付结果判定，不重造意图状态机。

最终 attestation 引用契约、策略、候选、满足义务的回执/评审/适用性判断及发现状态版本；它是已通过判定的快照，不是另一套可手工置绿的状态。历史完成事实与当前适用性分别展示。

## 7. 兼容、状态与模块边界

新 policy/review/findings 记录采用现有原子写、版本、校验和与锁模式，置于 reset 不清的家族；原运行和事件是事实源，索引可以重建但不能独立裁决。登记清扫、诊断和迁移家族，损坏在放行前 fail-closed。发现按任务/契约身份延续，supersede 不能开空账。既有历史 findings 文件不自动变成运行时发现。

Q9 兼容不靠“没有 policy 字段”触发：新注册格式必须带策略身份，缺失或损坏按错误处理；旧格式只允许已存在的目标及其既有队列记录延续，身份由旧记录、attempt/queue 来源及首次兼容快照关联。首次状态操作在锁内登记兼容来源，不在 update/sync 中写状态，也不从受损记录猜测身份。新建同名目标不能继承旧版资格。旧记录缺足够身份时停止并指向显式迁移。

旧目标保留原规则与结果标签；显式迁移先备份并保持外部事实和预算，补齐新策略及缺失证据，不将旧自报评审改名为受控运行。契约字节不变且授权仍有效时不凭空新增批准；契约改变或原来无契约时按现有契约批准机制处理。新目标若缺需求契约，可准备草案，但不得完成新策略采纳或宣称 0.4.0 交付 A。

主依赖链：**R0 → M0 → M1 → M2 → M3 → M4 → M5**。各阶段分为独立 HEAVY 实施目标，按现有计划审查与契约批准协议启动；下面的任务包是分阶段计划的输入，不能把未完成依赖绕成独立发布。

| R0：0.3.1 收口 | 按 companion plan 完成棒2、两项最小修复与 release-ready | 真实计量与两项失败反例修复齐备；冻结 full SHA/包哈希；未通过不开始正式比较 |

### 8.1 各阶段 QA 配方

以下 `scripts/v040/qa.mjs` 与 `scripts/evaluation/run-pairs.mjs` 是待新增的验收工具，必须由对应阶段实现并提供 `--help`；不表示当前可执行。qa 的调用形态为 `node scripts/v040/qa.mjs --case <id> --fixture <隔离根> --out <证据根>`。通用输出约定为 `result.json`（case、载荷/候选/环境身份、passed、逐断言结果）及原始 stdout/stderr、回执与状态文件哈希；通过 exit 0，失败或缺能力 exit 非0。不把缺能力算 SKIP 通过。

## 9. 三仓评估与发布判据

### 9.1 冻结与运行

每仓至少两个未用于调参的任务，各三次新旧策略配对：3 仓 × 2 任务 × 3 次 × 2 策略 = **18 对、至少 36 次真实运行**。每项三次中至少一次按可观测执行事件注入中断并恢复，两个策略使用相同触发条件；额外故障对抗与机制单测不充抵这 36 次。

开发集使用已知事故及旧消融/试点材料；独立评估集为新任务与独立判据。M0 由不承担策略调参的评价者准备并封存任务快照、缺陷、oracle、环境、预算、随机运行顺序和结果格式，调参者只知覆盖类别，不接触答案。任务执行代理取得需求但不取得隐藏判据。依赖组织和输入隔离，不宣称同权限文件系统是安全沙箱；泄露或被用于调参即作废该批独立性。

复用三个项目的准备配方，在独立夹具根运行，源码和兄弟依赖固定 SHA。每对固定模型、引擎、工具、任务、输入、CI要求及相同预算，记录载荷哈希；无法固定的环境变化分层说明，不混作因果结论。M0只做开发集探针，不提前运行正式旧臂；M5候选冻结后在同一实验窗口串行、按封存顺序交错新旧两臂，避免策略与时间混杂以及跨任务消耗混计。必要授权与 CI 先准备，缺失时 M0 阻塞；不得冒用本仓权限修改另一项目或伪造 UPS 事件。

所有尝试都入账。基础设施故障、429、超时、预算停止和不完整配对分别标记；保留原样本，不只重跑较差的一臂直到变绿。需要替换失效配对时整对重跑，记录原因和全部成本；有效配对数不足不报完成。候选策略冻结后才揭示独立评价；若据结果修策略，原批转开发资料，新候选须重新冻结未用于调参的评估集，不覆盖旧失败记录。

### 9.2 指标与决定规则（已确认）

- 正确交付：独立 oracle 确认契约终点；合法停止不计成功，系统宣布完成但 oracle 不满足计错误完成。
- 质量发布门：第10节预定义关键反例全部通过；新臂18次中关键错误完成为0；每个任务新臂至少2/3正确交付，正确交付总数不低于基线，并在错误完成减少或正确交付增加中至少一项严格改善。不宣称小样本总体错误率为零。
- 报告按项目、任务和配对列原始结果及差值；同时报告误阻断、错误复用、正确复用、人工介入原因、重复根因、重验量及耗时。
- 总成功成本：整臂所有尝试的模型消耗与真实开销总和/独立判定成功数；成功数为0则无可定义比值，不能报零成本。另列总消耗、失败开销、墙钟/等待时间，不把秒与积分直接相加。
- 成本上升不单独否决发布，但不能突破原授权预算；预算不足则保留未完成实验并提出下一步，不自动追加额度。
- 若质量与基线打平、只有更多流程记录，结论为尚无质量收益证据；不把“机制已实现”替代策略晋级依据。策略采纳仍需维护者决定，不自动修改在途契约、预算或任务队列。

报告计划路径：`docs/reviews/v040-policy-evaluation.md`；预注册与能力报告计划路径：`docs/spikes/v040-m0-report.md`。原始轨迹在本地产物目录保存，报告附哈希与可复核索引，凭据不入库。
