# 0.4.1 评估与 0.5.0 迭代建议

日期：2026-10-04。状态：**评估与实施建议，尚未成为现行决策或执行授权**。本文不修改 #42–#46，不把建议登记为已拍板，不替代 [挂账单源](debts.md)。

## 1. 结论

**0.4.1 完成了编排纪律的结构补齐，但没有新证据证明质量、完成效率或总成本改善。0.5.0 建议聚焦“可完成、可计量、可验证收益”。**

- 执行图单源、异议原语、观察 JSON 契约、双图视图均已交付；C1–C4 保持关账，不再包装成下一版新功能。
- 0.4.0 的历史配对评估暴露了无人值守完成流程摩擦和评估仪器问题；它不能直接证明 0.4.1 的效果。
- 0.5.0 先补评估完整性、异议文书一致性、评审计量与运行前检查，再补完成路径，最后在独立新评估集上重评。
- 发布可用版本与切换默认策略仍是两件事。维持 [ADR-0034](adr/0034-strategy-adoption-deferred.md)：未取得预注册门要求的证据，不宣称质量收益，不自动采纳。

## 4. 优先问题

### P0：正式重评前，评估器必须拒绝不完整样本

`scripts/evaluation/run-pairs.mjs` 的 `qualityGate` 按成功条数至少 2 判断任务，不自行保证三次 trial、两臂齐备、任务集合完整。`writeReport` 的完整性合取核 journal 链、包哈希与 Node 版本，未在该层核对冻结序列的完整配对；关键反例清单传空。

本次在 v0.4.1 直接调用 `qualityGate`，输入只有同一任务两条新臂成功记录、无旧臂，结果为 `met: true`。这是**函数边界的动态复现**，不是对历史批次缺失样本的指控，也未证明正常执行入口必然会生成这种报告。

验收：缺任务、缺任一臂、缺 trial、重复 trial、未知判读、身份/代次混杂必须产生明确的“不具备评估资格”；完整但质量不足另报“不满足质量门”。关键反例 ID 绑定批清单并逐项判读；trial 数变化时按预注册分母计算，不继续硬编码成功数 2。

### P1：异议文书哈希必须绑定实际复判输入

`core/findings.js` 登记 groundsSha256；发布版 `core/review.js:413–419` 在打包时重新读 groundsPath，没有对原字节哈希复核。探针确认：修改后，输入包携带旧哈希和新正文；删除后仍生成输入包，只披露正文缺席。

影响是文书审计绑定不可靠；本次未运行完整 adjudicate，也不声称因此已能绕过发现门。建议登记时封存文书，或复判前核对原始字节哈希、缺失/漂移就拒绝并给出重新提交异议的恢复路径。截断只影响展示，身份应绑定完整原文。需要新增“修改、删除、超长、改名后的文书”红绿与 CLI 场景。

### P0：已有计量与 provider 候选工作先完成验证

发布版 `querySessionPoints` 已支持隔离 HOME 子账本，但常规成本报表读取宿主库；未提交改动正在补 provider/model 用量、全局评审汇总与沙盒配置过滤。方向符合“消耗可解释”，不能仅因有代码就认定完成。

实施前必须核清：

- 实际 provider/model 与记录是否一致；未识别配置不能悄悄退回未经约束的整包配置。若采用 fail-closed，先定义兼容与恢复路径；这不意味着自研模型路由。
- 未计价和缺失保留独立状态及 tokens，不渲染为完整零成本；计价子集只能称已知下界。
- 重试、重复落账、两个同名项目、写入中断/失败如何去重和恢复；运行档为事实源，汇总可重建。
- 宿主库不存在或不可读时，沙盒账仍可独立展示。当前候选 `formatCost` 有宿主库早返回路径，需用该场景检验新汇总是否可达。
- 预算跨首轮、格式重试、恢复与失败运行累计，近似限制仍按 #32 执行；用户 config.json 零写入。

这些是现有候选增量的收口条件，不要求新建通用计费平台，也不预先认定所有风险已在生产发生。

## 5. 历史评估究竟证明了什么

来源：[0.4.0 配对报告](reviews/v040-policy-evaluation.md)。比较的是 0.3.1 基线与 0.4.0 候选机制包，共 18 对、36 次正式运行。

| 指标 | 基线 | 候选 | 解释 |
|---|---:|---:|---|
| 密封 oracle 正确交付 | 12/18 | 12/18 | 持平；lz 腿判据有环境假阴性 |
| 宣称完成 | 18/18 | 0/18 | 候选收尾流程存在明显摩擦；不能把不声明完成当成质量提升 |
| 错误完成，原判定器口径 | 6 | 0 | 旧 6 例受 lz check-2 假阴性影响，不足以证明减少真实错误 |
| probe 反事实正确交付 | 18/18 | 18/18 | 仅敏感性分析；不可替换密封正式结果 |
| finish 义务门拒绝 | 0 | 19 次 | 候选 12 次拒绝发生在 oracle 已正确之后；尚须逐义务归因，不能全部叫误阻断 |
| 平均墙钟 | 18.4 分钟 | 23.1 分钟 | 候选增加 4.7 分钟，约 25.5% |
| 已记录积分 | 170.83 | 98.43 | 部分计量约低 42.4%；29/36 可计量，7 条缺失全为超时，不能宣称完整总成本降低 |

历史报告还混用了两种失败解释：其 §2 表格称判据 6 在原始口径通过，表后却写判据 6 失败。应补勘误，保留原记录：原始 oracle 判据 4 未过；probe 反事实下判据 6 无严格改善；两者都不支持采纳。不能为使结论好看而改旧密封判据或覆盖旧失败记录。

下一批同时报告四种结果：正确且完成、正确但未完成、错误却完成、错误且未完成。成本分完整批全部尝试与最终有效配对两账，包含失败、重跑、恢复及 canary；缺失量独列。墙钟与积分分列，不混成一个分数。

## 6. 0.5.0 迭代顺序与验收

依赖顺序：**M0 → M1 → M2 → M3 → M4**。M0 的评估仪器与异议小修可独立并行；M1 的产品完成路径和计量增量在冻结候选前都必须闭合。以下均为建议范围。

| 阶段 | 交付与主要位置 | 退出标准 |
|---|---|---|
| M0：基线与仪器可信 | `scripts/evaluation/`、其契约测试、历史报告勘误；异议输入绑定修复 `core/review.js` / `core/findings.js` | 正/负 oracle canary 双向正确；不完整批必拒；代次、环境与包身份可核；文书漂移红绿成立；保留旧批记录。覆盖 A1/A5 的工程准备 |
| M1：无人值守可完成、用量可追 | 先归因旧 19 次 gate 拒绝；形成 A2 语义 ADR 草案；沿 `core/gate.js`、`core/review.js`、`core/drive.js` 及既有 skills 补路径；收口已有 cost/doctor/provider 增量 | 真宿主正常流程可完成；缺评审、open/contested 发现、漂移证据、失效授权继续拒；预算耗尽诚实停止；重试与恢复无漏账/双算；宿主账缺席仍可观测子账 |
| M2：设计与候选冻结 | A3 任务/预算设计，A4 采纳判据说明，独立新评估集、manifest 与 README | 开发集先选“任务分级预算”或“任务瘦身”；每对同模型/引擎/输入/预算/CI要求；固定版本包哈希、seed、trial数、重跑与停止规则。实现方不得读新密封任务 |
| M3：正式重评 | `run-pairs` 全部尝试账、四格结果、逐对差值、计量完整性与恢复报告 | 预注册配对齐备、判读代次统一；中断恢复与关键负例逐项可核；缺失计量不记零；读过正式任务再调参则整批独立性作废并换新集 |
| M4：发布与采纳分开结案 | 回归/真实表面证据、release checklist、A1–A5 处置与决策同步 | 发布机械门满足后可形成 release-ready；采纳门未过继续保留负结论。更改现行决策时同步 ADR、decisions 和 AGENTS；发布、推送与默认切换另依明确授权执行 |

### M1 的语义建议

优先让义务有可执行满足路径：自动获取受控独立评审、使用已存在的合格复用、对确已消失的额外义务走独立复判。`headless` 不是豁免理由，oracle 正确也不替代产品契约中的评审或交付义务。

若确需“本地已验证、待外部条件”的部分满足结果，须在 A2 ADR 明确它与完成的区别：不写 LOOP_COMPLETE、不授权合并/部署、不绕过 B/C 或发现门。停止原因与下一步动作先通过现有文本/JSON 表达，不先发明另一套完成状态机。

### M2 的实验建议

- 主比较使用 **v0.4.1 稳定基线 vs 冻结的 0.5.0 候选**，回答下一版是否有增量收益。#42 的旧策略采纳若与该基线不等价，应另列“既有默认策略 vs 候选策略”的预注册比较；两问题分开，不能用版本对比冒充默认策略消融。
- 延续每任务 ≥2/3、总正确交付不低于基线、关键错误完成为零、质量至少一项严格改善。若另提“质量不劣且收尾更顺畅”的产品标准，须事前单列，不能据此宣称质量提升或事后降低原采纳门。
- 从新任务覆盖实际风险和恢复能力；既有已见缺陷属于开发集。每任务 3 trial 是沿用的最小设计，不支持总体错误率或普遍收益结论。
- 正式批前锁定墙钟与积分总预算：两臂 × 任务数 × trial数，并单列 canary、独立评审和失效重跑额度。上限取开发集测量结果，本报告不编造费用或工期。

## 7. 范围边界

0.5.0 不主动重开 H3R 升格、fast 默认化、HEAVY workers、watch/HTTP/wire/viewer、自由消息协议、非 Git finish 或模型路由。这些已有终拍或触发器，未满足触发条件继续维持；来源为 [债账 B 线与休眠账](debts.md)、[文书协议 ADR](adr/0035-document-protocol.md)。

停止条件：本次评估在发布版对象核清、关键结论有来源、风险可复现或明确静态边界、迭代依赖与退出标准成文后完成；本次不实施整个 0.5.0。
