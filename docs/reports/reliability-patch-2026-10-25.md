## 已实施

- `core/sandbox-usage-lock.js`：跨进程短临界区、5 秒有界等待、不可重入、强杀后的 OS 锁释放。协调文件无表、无消费数据；不能在写者运行时删除或替换。
- `core/cost.js`：读取／判重／追加共锁，JSONL 刷盘后回执；损坏历史阻止继续写入。累计快照统一差量计算，来源向量不单调、缺实例却遇到已有具名实例、同事件身份出现增长读数时均拒绝猜测或静默丢量。
- `core/review.js` 与 harvest：运行档继续保存完整消费，聚合账只追加尚未覆盖的差量。新记录携会话集合，支持同运行集合扩展；旧实例无法确定谱系时具名阻塞并保留补账事实。
- spool：项目与事件摘要命名、原子替换；缺身份回执分别保留，旧 pending 不自动销账，不充当重放队列。
- D2：交付对象／数组 provenance 保形，字符串与 null 的既有派生不变。D3：harvest 输出实际目的地；并修正 Windows 路径分隔符解析，真实 Windows 来源测试覆盖。
- README／guide：中英文将独立评审 OS 沙盒改为“0.6.0 起已发布”，补齐英文原来缺失的 app-layer／OAuth 分级说明，保留旧外部锚点；明确普通独立进程组后代与 cleanup 的文件清理边界，预算说明对齐积分近似限制和在途超额事实。

## R0 红证据与边界

源码复核发现，当前安装的 ZCode（壳 3.16.3，引擎 0.17.0；源码 SHA-256 记入本地 `engine-baseline.json`）普通 shell 创建在 POSIX 上使用 detached 进程组。本仓现有 group kill 只覆盖自己的组。离线探针结果：

| 平台 | 普通 headless 超时后代 | 四进程同事件追加 | 两项目同 runId spool | 显式进程组与 detached 后代 |
| --- | --- | --- | --- | --- |
| macOS arm64／Node 24.19.0 | 返回后心跳继续，失败 | 4 行／4 份消费，失败 | 仅 1 份，失败 | 同组停止；另起组仍写入，失败 |
| Linux arm64／Node 24.22.1 | 返回后心跳继续，失败 | 冻结红记录为 3 行／3 份消费，失败 | 仅 1 份，失败 | 同组停止；另起组仍写入，失败 |
| Windows 11 arm64／Node 24.19.0 | 此单一探针通过 | 3 行／3 份消费，失败 | 仅 1 份，失败 | `processTree` 具名拒绝；完整生命周期未通过 |

并发竞态行数受调度影响，验收要求始终是恰好 1 行；3 或 4 都构成反例。Windows 的单一超时结果不证明跨段后台、workers、嵌套评审或控制器强杀后的恢复。所有探针均使用自写假引擎与有限寿命本地子进程，未调用模型。

现有正常退出也杀组的行为会破坏跨分段后台复用。仅换负 PID kill、按进程名扫描或定期轮询父子树，不能证明“启动先归属、孤儿可恢复、PID 复用不误杀”。本轮未引入这些无法满足契约的替代方案。

后续 R0 必须先给出并实测平台原语：Windows 可验证 Job Object；Linux 可验证有实际委派权限的 cgroup；macOS 须验证宿主协作的启动前归属或有足够 OS 能力的监督机制。前两者的文档存在不等于本仓已实现，macOS 方案尚未证明。若需要新原生组件／宿主接口，须先补具体接口、打包与兼容设计，再按既定三平台门测试，不能把文档设想当完成证据。

最小替代提案是把下一次 R0 限定为一个**启动前归属的托管后端**验证：接口只提供能力检查、创建运行、在归属完成后放行执行、停止并核验、按持久身份恢复；记录 runId／fence／后端身份，禁止以裸 PID 恢复。Windows 候选为原生 Job Object 适配器；Linux 候选为可委派 cgroup；macOS 优先要求宿主提供可验证的子进程启动协作接口。现有 Node 进程组路径已被反例否决，但本轮尚未验证新后端或取得 macOS 所需宿主能力，不能宣称它们在现有支持面可交付。引入原生载荷或改变宿主接口属于原计划要求提出取舍的边界，本轮没有修改已安装的 ZCode 或放宽三平台完成门。

参考：[Node 24 进程接口](https://nodejs.org/download/release/v24.0.0/docs/api/child_process.html)、[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)。本记录的失败判断来自本地探针，未以参考文档替代实测。

Windows skip 是既有 `authDir chmod 555` POSIX 权限构造；跨平台“授权目录被普通文件占位”的写失败检查已通过。该 skip 不覆盖本次新增账本门，也不代表该 POSIX 权限场景在 Windows 已验证。Linux 只验证实际 Linux 容器环境，不扩大为所有发行版或 cgroup 能力证明。

账本验收映射：A01/A02 由真实并发、跨项目／实例／月份检查覆盖；A03 由累计快照交错与真实来源 harvest 覆盖；A04 的锁竞争、强杀、丢确认和坏行检查进入三平台聚焦套件，实际磁盘满与 POSIX 权限拒绝仅在 Linux tmpfs 验证；A05 增加并发 spool 与缺身份回执保留；A06 保留旧行／旧名回执及错误目标检查；A07 包含字符串／null／对象／数组，以及不支持类型拒绝后的结算完整回滚。**没有三平台真实磁盘满的完整矩阵，也没有补丁所需的 P01–P08 生命周期绿证据。**

证据保留在本地忽略目录 `artifacts/reliability/`：三平台 R0 红记录、containment 反例、`accounting-red.tap`、`d2-red.tap`、`identity-red.tap`、各平台聚焦日志、三次全套日志（978 项首次、979 项中间候选、981 项最终候选）、打包记录、全局真账摘要与候选 manifest。磁盘满首次探针误以为一定先在 JSONL 追加处失败，实际先被 SQLite 事务入口拒绝；修正夹具以分别覆盖两层后通过，首份错误断言日志仍保留。Windows SQLite CLI 来自官方发布包，校验上游 SHA3 后仅置于该批临时目录，不改系统 PATH。没有提交这些可能含本机路径的原始日志。
