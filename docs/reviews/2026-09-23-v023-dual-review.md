### V023-R2-B-1 · P2 · 记账排除的 `node …lzy.js` 分支在含空格路径下失配——预期记账形态被误 deny
- 位置：plugin/hooks/h3r-pretool.js:33-34；联动 core/drive.js:81-84
- 现象：排除正则 `/^node\s+\S*cli[\\/]lzy\.js\b/` 与 `/^node\s+\S*lzy\.js\b/` 用 `\S*` 匹配路径，
  无法跨越任何空白字符。win32 全局安装的 cliPath 形如
  `C:\Users\<含空格用户名>\AppData\Roaming\npm\node_modules\lazyzcode\cli\lzy.js`（npm 全局根在
  用户 profile 下），加引号后引号字符+空格使 `\S*` 必然失配 ⇒ 记账排除对该环境**静默失效**。
  而 drive 段提示词（core/drive.js:81,84）恰恰指示模型用 `node ${cliPath} step done <ID> --note …`
  调 CLI，且本目标的预期形态（h2 步标题含「rm -rf build-cache/」进 `--note`）意味着命中词表的
  记账调用会被 deny——段内 `step done` 永远过不去，模型重试到墙钟尽，trial 读数被污染为
  「误停」而非「门检出」。ADR-0022:64 与钩子头注 :26-28 承诺的「排除仓库自身记账通道」在该
  环境不成立。契约测试测不到：execRepo 的 CLI 路径在 mkdtemp tmpdir 下（无空格）。
- 复现/证据：对 `node "C:\Users\John Smith\...\cli\lzy.js" step done N1 --note "执行 rm -rf x"` 逐字
  套用 :33 正则——`\S*cli[\\/]lzy\.js` 要求从 `node ` 后到 `cli/lzy.js` 为连续非空白串，
  `John Smith` 的空格截断之 → isBookkeeping 返回 false → 词表命中 `rm -rf` → deny。
  测试面反证：test/h3r-enforcement.contract.test.js:204 的排除用例 CLI 为无空格绝对路径。
- 影响：边界/一致性（P2）——armed 形态下特定环境（空格安装路径）的记账面假阳性死循环；
  休眠态与无空格路径环境不受影响。
- 建议：排除判定改为对命令做引号感知/取 basename（或 `/cli[\\/]lzy\.js\b/` 无锚点匹配 +
  前置 `^node\s` 即可），并补一个含空格路径的契约用例。

### V023-R2-B-2 · P2 · 「钩子崩溃/超时/坏 schema ⇒ 引擎侧 fail-open（工具照常执行）」未经引擎源或活体验证，引擎源显示非 0/非 2 退出走抛错路径
- 位置：plugin/hooks/h3r-pretool.js:14-16；docs/adr/0022-h3r-lane-boundary.md:64；
